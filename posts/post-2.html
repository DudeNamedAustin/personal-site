Building a Security-Focused Homelab

March 2026

The best argument I have for building a homelab is that it lets you break things deliberately. Production environments punish experimentation. A lab rewards it.

Mine started as a single repurposed machine and grew into something I now rely on for testing Azure integrations, running local LLM inference, and experimenting with the kind of infrastructure configurations I'd never want to first encounter at work. Here's how it's structured and why.

Hardware foundation

The core is a small form-factor machine with enough CPU cores and RAM to run several VMs concurrently. I run Proxmox as the hypervisor — it's stable, well-documented, and free. The important thing isn't the specific hardware; it's having enough headroom that resource contention doesn't become the variable you're accidentally testing.

For storage, I separate OS disks from data. Snapshots before significant changes are non-negotiable. The ability to roll back in 30 seconds removes a lot of the anxiety from experimentation.

Network segmentation

The lab network is isolated from the rest of my home network. VMs that need internet access go through a dedicated VLAN and a firewall that logs everything. This isn't paranoia — it's good practice, and it mirrors the segmentation decisions I'd make in a real cloud architecture.

I use pfSense for routing and firewall rules. The configuration is version-controlled so that rebuilds are repeatable. If I need to recreate the environment, I can.

Azure integration

A significant part of what I test involves Azure connectivity. I use Azure Arc to onboard local VMs as Arc-enabled servers, which lets me apply Azure Policy and test Defender for Cloud recommendations against machines I fully control. It also lets me experiment with Azure Monitor and Log Analytics without incurring cloud VM costs.

Testing Entra ID configurations — Conditional Access, app registrations, managed identity scoping — against a real tenant with real resources beats any documentation. I keep a dedicated non-production tenant for this purpose.

Local LLM workloads

More recently I've been running local inference with Ollama. The primary use case is keeping sensitive data off third-party APIs while still being able to experiment with LLM-assisted tooling. I've built small scripts that use local models for log summarization and draft detection rules — nothing production-grade yet, but useful for understanding where these tools actually help and where they don't.

What the homelab teaches

The consistent lesson is that complexity accumulates faster than you expect, and good defaults matter. Every security control I've tested here — network segmentation, identity scoping, logging coverage — has revealed a gap between what I thought was configured and what actually was.

That's the point. Find it in the lab. Fix it there. Don't find it somewhere worse.
