Identity as the Modern Control Plane

March 2026

For most of computing history, security started with the network. You drew a perimeter, controlled what crossed it, and trusted what was inside. Firewalls, VLANs, and DMZs were the vocabulary. If traffic came from the right IP range, it was probably fine.

That model is functionally dead in a cloud-first world, and identity is what replaced it.

When your workloads run across Azure, your users authenticate from home networks and coffee shops, and your data lives in SaaS platforms you don't control the infrastructure of — the network boundary stops being meaningful. What remains consistent is identity. Every request to access a resource carries a principal: a user, a service principal, a managed identity. That principal is the thing you can consistently evaluate, control, and audit.

The shift in practice

In Microsoft Entra ID, this becomes concrete fast. Conditional Access policies let you express controls that would have required complex network topology a decade ago: require MFA when a user's risk score is elevated, block legacy authentication protocols, enforce compliant device state before granting access to sensitive apps. None of that is firewall logic. It's all identity logic.

Workload identity takes it a step further. A virtual machine or container shouldn't be authenticating with a stored credential — it should have a managed identity with scoped role assignments, evaluated at request time by the authorization system. The secret you never have to rotate is the one that doesn't exist. That principle only holds when identity is your control plane.

Where this breaks down

The gap I see most often isn't in the tooling — Entra ID is genuinely capable — it's in how identity architecture gets treated as an afterthought. Access is over-provisioned because scoping it properly is more work upfront. Privileged roles get assigned permanently because Privileged Identity Management requires enrollment and process change. Service accounts accumulate permissions because nobody owns auditing them.

The network perimeter failed the same way. Not because the tooling was wrong, but because security was bolted on after the architecture was built. Identity is the new perimeter, which means it earns the same fate if you treat it the same way.

The right framing

I've found it useful to think about identity not as an authentication layer but as the policy enforcement point for everything else. Who can do what, from where, under what conditions — all of that lives in the identity plane now. Designing a cloud system means designing the identity model first, not retrofitting it at the end.

That reframe changes what you build, in what order, and how you evaluate whether a system is actually secure. The network is still there. It still matters at the edges. But the control plane is identity, and building as if it isn't is how breaches happen.
